# AD-149 — a masked secret names its cause, advises the fix once, is counted in the session report, and never reaches disk

- **status**: active

## Decision

1. **`classifyLeak`** (`src/core/secret-scan/secret-scan.cause.ts`) decides a cause from the command and the file,
   never from the value:
   - `argv-credential`: the command line itself carried a secret, or a `-p…`/`--password`/`Authorization:` shape;
   - `logged-credential`: a log reader on a `.log` file or a `logs/` path, or a platform `logs` command;
   - `env-dump`: `env`, `printenv`, `set`, `export -p`;
   - `hardcoded`: a source or config file was read;
   - `other`: anything else.
2. **Advice once per session and subject.** `tool-after` appends one `[SECRET-HYGIENE <cause>]` line to the masked
   output. The line names the subject (the command with its own secrets masked, or the file's relative path) and
   the variable names, then the fix. `adviseOnce` keeps it to the first time a session meets that cause and
   subject; later reads are masked silently.
3. **The operator's record.** A `secret.masked` signal event carries `cause`, `kinds` and `subject`. The session
   rollup counts it in `secretsByCause`, keeping five subjects per cause. `tlc harness obs report` and its markdown
   copy show a **Secret hygiene** section.

4. **Persisted records are masked by the output rail's scan.** `redactDeep` (the path every obs attribute and
   every audit payload takes to disk) applies `scanForSecrets` with the known values and the signatures before its
   old three-pattern list. It does not apply the entropy pass, whose alphabet includes `/` and would mask temp
   paths and diagnostics. Known values are read only when `secrets.knownValues` is on, carried as
   `maskKnownValues` in the obs config and as an argument to `recordAudit`.

## Why

**The mask hides a symptom.** A credential in a tool's output was put there by something — a logger, a literal,
a command line, an environment dump — and the next run will print it again. Naming the cause is what turns the
redaction rail from a filter into feedback the code can act on.

**No exception for debug logs.**
- A debug level reaches production by misconfiguration.
- Logs travel to aggregators, CI artefacts and crash reports.
- In an agent workflow, the debug log is exactly what the agent reads while running the program.
- Whether a call is "debug" depends on runtime configuration the hook cannot see.

The advice therefore says *at any level, debug included*. It points at what debugging a credential actually
needs: which secret was loaded and whether it works, meaning presence, length, source and an HMAC fingerprint.
That never requires the value.

**Once, and with an exit.** Repeating the advice on every read of the same log would spend context on what the
agent was already told. Saying "if fixing this is outside your task, tell the operator" keeps the advice from
hijacking the turn it appears in.

**Names, never values, in every record.** The subject is masked with the same scan, and the kinds are signature
names or variable names. The report can be pasted into a pull request.

**The harness must not be the leak it reports.** The end-to-end check for this decision searched the state
directory for the test password and found it four times. Three were in `audit.jsonl`, the raw PostToolUse payload.
One was in `debug.jsonl`, the `shell.end` command line of a `mysql -p…`. Both reach disk through `redactDeep`,
which knew `ghp_`, `sk-` and `xox` only.

## Trade-offs

**The classification is a heuristic on the command text.** A log read through a wrapper the patterns do not know
lands in `other`, with generic advice. It never lands in a wrong cause that would mislead, because the fallback is
`other`.

**Hosts that cannot rewrite the event lose the advice with the mask** (Cursor's shell output, per
[/decisions/ad-124.md](/decisions/ad-124.md)). The `secret.masked` record and the report still carry it.

## Not decided here

- A stop gate over the turn's added lines that refuses logging a secret-named value at any level while allowing
  metadata (`len(x)`, `fp(x)`, `redact(x)`).
- Detecting a `.env` that is tracked by git.
- Language-specific advice, chosen by the file's extension or the project's manifest.
