# AD-148 — known secret values are masked by value, a masked placeholder cannot be written back, and Bash output reaches the mask

- **status**: active

## Decision

1. **`secrets.knownValues`** (default `true`, effective while `secrets.redactOutput` is on). `loadKnownSecrets`
   (`src/core/secret-scan/secret-scan.known.ts`) reads sensitive-named variables from the hook's environment and
   from the project's `.env` files (templates excluded, the same `isEnvFile` rule the floor uses). It adds the
   password inside any `scheme://user:password@` value. `scanForSecrets` takes those values as an optional second
   argument and masks every exact occurrence, longest first, as `[REDACTED:env:<VARIABLE>:<hash>]`, ahead of the
   signature and entropy passes. The excluded cases are:
   - the shell's `PWD`/`OLDPWD`;
   - names ending in a pointer suffix (`_PATH`, `_URL`, `_SOCK`, …);
   - values that are themselves paths;
   - values shorter than six characters.
2. **`secret-placeholder-write`.** In `tool.before`, after the operator rules, a write whose `proposedContent`
   contains a placeholder **this session handed out** (`sessionPlaceholders`, read from the existing redaction
   store) is denied, naming the placeholder and the file. A placeholder-shaped string the session never produced
   passes.
3. **Claude's Bash and MCP output reach the rail.** `claude.inbound.ts` sets `toolOutput` on `shell.after` and
   `mcp.after` from `tool_response`, as it already did for the generic tool kinds. `toolOutputRewriteOn` adds
   `shell.after`, `mcp.after` and `edit.after`, the three kinds PostToolUse fans out to besides `tool.after`.

## Why

**A credential in a log is usually a password a person chose.** Measured against the shape scan:
`password=hunter2`, `Xk9#mP2$vL8@qR4!wT7&` (28 characters, symbols cut it into runs shorter than the entropy
floor), `correct-horse-battery-staple-42` and `postgres://app:S3nh4F0rt3@db` all passed unmasked. Lowering the
entropy threshold or widening its alphabet would mask regexes, hashes and fixtures in source the agent is editing.
Matching the values already known to be secrets has no such cost: it masks nothing that is not one.

**The name filter applies to `.env` too.** Those files also hold `PORT=3000` and `NODE_ENV=development`. Masking
every `development` would be the false positive that gets the rail turned off.

**Masking a read is only safe if the mask cannot be written back.**
- An `Edit` whose old text holds a placeholder fails by itself, because the text is not on disk.
- A `Write` of the whole file succeeds, and replaces the credential with the placeholder silently.
- Keying the guard on the session's own placeholders, not on the pattern, keeps it from refusing this repository's
  own golden files, which contain placeholder-shaped strings on purpose.

**The Claude gap was found by the test for decision 1, not by review.** A `cat app.log` through Bash in Claude
Code produced a `shell.after` event with no output, so neither the shape scan nor anything else ever saw what the
command printed. The capability comment already said `updatedToolOutput` covers every event the adapter fires
PostToolUse for. The list stopped at `tool.after` because the fan-out kinds had no output to rewrite until now.

## Trade-offs

**The hook reads environment variables and `.env` files on every tool output.** It never shows or persists them;
only the hash of a value that was actually masked reaches disk, as before. An operator who does not want even
that sets `secrets.knownValues: false`.

**A secret stored anywhere else is not known**, whether in a vault, a file with another name, or a variable whose
name has no sensitive word. The shape scan still covers what it covered.

**Claude's untrusted-content rail now sees Bash and MCP output too.** It reads `toolOutput` on after-events, and
until now Claude gave it none on those kinds. This is the behaviour the rail was written for. It is stated here
because it changes what that rail sees on this host.

## Not decided here

- A `key=value` and URL-credential rule for shell output with no known value behind it.
- Classifying the cause of a leak (a logged credential, a hardcoded one, one passed on the command line) and
  suggesting the fix to the agent and the operator.
- A stop gate over the turn's added lines that refuses logging a secret-named value at any level, debug included.
- Floor coverage for `grep`/`sed`/`awk`/interpreters reading secret paths, and for vault CLIs run by the agent.
