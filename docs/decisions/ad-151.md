# AD-151 — personal data is pseudonymised in what a tool returns, refused in what a turn writes, by the project's own template

- **status**: active

## Decision

1. **A project template, `.tlc/harness/pii.json`.** It declares what personal data is for that project:
   - `extends`: packs on three independent axes, distributed with the runtime (`src/core/pii-scan/pii-scan.packs.ts`):
     - `id:<country>`: document detectors with their checksums — `br` (CPF, CNPJ), `es` (DNI/NIE), `fr` (NIR), `ar`
       (CUIT/CUIL), `in` (Aadhaar), `ca` (SIN) — and label-only documents (`us` SSN, `uk` NINO, `pt` NIF, `de`,
       `it`, `mx`, `au`);
     - `lang:<language>`: field names in `en`, `pt`, `es`, `fr`, `de`, `it`;
     - `domain:<sector>`: `finance`, `hr`, `health`, `special`. Health and the GDPR art. 9 / LGPD sensitive categories
       use `mode: "mask"`, with no visible attribute.
   - `fields`, `patterns` (each with an optional `validate` from a closed list: `luhn`, `mod97`, `br-cpf`, `br-cnpj`,
     `pt-nif`, `es-dni`, `fr-nir`, `verhoeff`, `ar-cuit`, `au-tfn`, `e164`, `card`), `fixtures.domains`,
     `fixtures.paths` and `keep`.

   With no file, the default is international: `global`, every `id:` pack whose free-text detectors are checksummed,
   and every `lang:` pack. The template is policy. `isPolicySurface` refuses an agent's write to it, and
   `policySourceFingerprint` hashes it, so an out-of-band edit trips `policy-baseline-divergence`.

2. **Read: pseudonymise.** In `tool.after`, after the secret mask, `scanForPii` runs on what is left. It has three passes:
   - labelled values: JSON fields, `key=value`, `key: value`, and psql/mysql/CSV/sqlite `-header` tables, by column;
   - self-proving value shapes: mailbox, E.164 phone, Luhn-and-prefix card, mod-97 IBAN, checksummed documents;
   - project patterns, which run first.

   Each value becomes `[PII:<kind>:<hmac8><attribute>]`. The HMAC uses a per-machine salt in the runtime state, which
   the floor treats as a secret, so the token is stable across sessions on that machine and cannot be recomputed from
   the value. The kept attributes are an email domain, a phone's country code, and a card's brand and last four. In a
   source file only the value pass runs.

3. **Source decides the advice, never the mask.** `classifyPiiSource` names the source:
   - `db-query`: a database client anywhere in the command, including `docker compose exec`, `docker exec`,
     `kubectl exec … --` and `ssh host '…'`; `aws|awslocal dynamodb`; an MCP tool named for a database;
   - `api-response`, `log`, `data-file`, `source-file`, `config-file`, `other`.

   The advice, given once per source and subject, tells a query to aggregate in the query or a script, and tells a
   log, source or config file to fix the code that put the data there.

4. **Write: refuse at stop.** `findAddedPii` reads the turn's added lines (`listAddedLines`). In a source file only
   self-proving shapes count; in config, log and data files labelled values count too. A finding sends the turn back
   with `file:line (kind)` and never the value. `fixtures.paths` skips a legitimate seed. Writing a token this
   session handed out back into a file is refused in `tool.before` (`pii-placeholder-write`).

5. **Disk.** `redactDeep` masks personal data as `[PII:<kind>]` in audit and obs records, with no hash, so the writer
   never needs the salt.

6. **Operator surface.**
   - `pii.redactOutput` and `pii.blockWrites` are on by default;
   - turning either off records `pii.disabled` at session start;
   - `pii.masked` and `pii.written` feed a `PII exposure` section in the session report;
   - `doctor` shows the template's packs and errors;
   - `tlc harness pii suggest` proposes a template from schema files, ORM classes in the common languages and
     locale folders, and `tlc harness pii test` shows what would be pseudonymised by line and kind, without values;
   - the `harness-pii` skill reads the domain model the patterns cannot and passes its judgement to
     `pii suggest --candidates`, which keeps only names, kinds, modes and evidence.

## Why

A query result is the one place personal data legitimately appears in an agent's work, and it was the one place
nothing protected. Measured on a live session, a `.env` read and an earlier `grep` sent a developer's mailbox and a
signing secret to a model provider through a router. Names and mailboxes from a users table would have gone the same way,
because the redaction only knew credential shapes.

A local container is not a lesser case. `docker compose exec db psql` returns the rows a production psql would, so
the source classifier asks which client ran, never where the database lives.

Masking alone would end analysis. A stable pseudonym keeps counts, joins and duplicates, the visible attributes keep
the coarse questions (which domains, which countries) answerable, and the advice moves raw-value work into the query
or a script, where the values never cross the model.

What is personal data differs by product. A finance app's account number, a clinic's patient id and a test suite's
`@e2e.test` users cannot be one global list. Packs make the common cases one word each, and the template makes the
rest the project's call, reviewed like the rest of its policy.

## Trade-offs

- **Free-text names and addresses are not recognised.** Without a field name beside them, a name is a word. The
  detector covers labelled data, which is what APIs and databases return, and documents the gap.
- **Field names can mislead.** A column named for a label masks its values whatever they hold. In code, a field
  name labels a variable, so the label pass is off for source files and values shaped like code are skipped.
- **Checksums are probabilistic.** Roughly one random number in a hundred passes a mod-11 check, which is why short
  unformatted documents are label-only and formatted ones are matched anywhere.
- **The salt is per machine.** Tokens from two machines do not match, and losing the salt changes every token.
- **Hosts that cannot rewrite the firing event's output** degrade to a context warning, and the value has already
  reached the model there.
- **`pii suggest` reads schema files, never data,** and proposes only. The template is saved by the operator.
- **The skill judges and the CLI compiles.** A domain class in any language is read by the agent, which knows that
  `titular` on an account is a person. The CLI turns those names into the template, because a label or a pack name
  the agent got wrong would otherwise produce a template that looks valid and protects nothing.
- **An identifier under `name` is not a person.** A manifest's package name, a descriptor's field name and a
  camelCase key read in the clear; a single lower-case word under a bare `name` does too, which is the one case a
  store that lower-cases first names gives up.

## Not decided here

- A detector for names in free text, by dictionary or model.
- Per-column policy beyond pseudonym or mask, such as format-preserving tokens or hashing a value for a join key.
- Masking inside binary or compressed output, images, or a recursive search's results beyond what the output text
  shows.
- Whether a handler that throws mid-call should fail closed on every provider.
